Como estudar neste curso

Este material foi organizado para quem está começando e quer aprender fazendo. Você não precisa memorizar tudo de uma vez: leia o conceito, execute o exemplo, modifique uma parte e só então avance.

1. Entenda Leia a explicação e compreenda o problema que o recurso resolve.
2. Pratique Copie o exemplo, execute no Python e altere os valores para testar.
3. Construa Use o que aprendeu no projeto-guia e resolva os exercícios.
Projeto-guia: gerenciador de tarefas

Ao longo do curso, você vai desenvolver um pequeno programa de terminal: primeiro cadastra tarefas, depois organiza prioridades, trata erros, salva os dados em arquivo e, por fim, separa o código em módulos. Assim, cada conceito aparece em uma situação concreta.

Alterando o título e a descrição

Por padrão, o título do site é username.github.io. Para personalizar a página do GitHub Pages, você pode alterar o título e a descrição do site editando o arquivo _config.yml no repositório.

  1. Abra a guia Código do repositório.
  2. Verifique se o arquivo _config.yml já existe. Se não existir, crie um novo arquivo com esse nome.
  3. Abra o arquivo _config.yml e clique em Editar.
  4. Adicione duas linhas: title: com o título desejado e description: com a descrição do site.
  5. Quando terminar, clique em Confirmar alterações.
theme: jekyll-theme-minimal
title: Octocat's homepage
description: Bookmark this to keep an eye on my project updates!

Esse ajuste ajuda a melhorar a aparência e a identidade do seu site no GitHub Pages, além de deixar o nome e a introdução mais profissionais e compreensíveis para visitantes.

3. Características Principais

  • ✅ Sintaxe clara e legível — próxima da linguagem natural
  • ✅ Multiparadigma — suporta POO, funcional, procedural e imperativa
  • ✅ Tipagem dinâmica — não é necessário declarar o tipo das variáveis
  • ✅ Interpretada — o código é compilado automaticamente para bytecode e executado pelo interpretador
  • ✅ Multiplataforma — funciona em Windows, macOS, Linux e outros sistemas
  • ✅ Gerenciamento automático de memória (garbage collector)
  • ✅ Baterias incluídas — a biblioteca padrão é muito extensa
  • ✅ Indentação obrigatória — ajuda a manter o código organizado
  • ✅ Código aberto e gratuito
  • ✅ Grande comunidade global

7. Estruturas de Controle

Condicionais

if idade >= 18:
    print("Maior de idade")
elif idade >= 12:
    print("Adolescente")
else:
    print("Criança")

Laços

# for
for i in range(5):
    print(i)

# while
contador = 0
while contador < 5:
    print(contador)
    contador += 1

# List comprehension
quadrados = [x**2 for x in range(10)]

9. Orientação a Objetos

# Classe base (pai)
class Animal:
    def __init__(self, nome):
        self.nome = nome

    def fazer_som(self):
        pass  # método a ser sobrescrito

# Classe filha
class Cachorro(Animal):
    def __init__(self, nome, raca):
        super().__init__(nome)
        self.raca = raca

    def fazer_som(self):
        return f"{self.nome} diz: Au au!"

dog = Cachorro("Rex", "Labrador")
print(dog.fazer_som())  # Rex diz: Au au!

# Outra classe filha (Herança)
class Gato(Animal):
    def fazer_som(self):
        return f"{self.nome} diz: Miau!"

gato = Gato("Felix")
print(gato.fazer_som())  # Felix diz: Miau!

10. Tratamento de Exceções

try:
    numero = int(input("Digite um número: "))
    resultado = 10 / numero
except ValueError:
    print("Valor inválido!")
except ZeroDivisionError:
    print("Divisão por zero!")
except Exception as e:
    print(f"Erro: {e}")
finally:
    print("Fim")

12. Boas Práticas (PEP 8)

Boas práticas tornam o código mais fácil de ler, revisar e manter, especialmente quando outras pessoas participam do projeto.

  • Use 4 espaços por nível de indentação
  • Limite as linhas a 79 caracteres
  • Use snake_case para variáveis: minha_variavel
  • Use CamelCase para classes: MinhaClasse
  • Use MAIÚSCULAS para constantes: TAXA_JUROS
  • Docstrings para documentar funções e classes
  • Ferramentas úteis: black, flake8, pylint, mypy

14. Zen of Python (PEP 20)

Bonito é melhor que feio.
Explícito é melhor que implícito.
Simples é melhor que complexo.
Legibilidade conta.
Deveria haver um — e, preferencialmente, apenas um — modo óbvio para fazer algo.
Agora é melhor que nunca.
Se a implementação é difícil de explicar, é uma má ideia.
Namespaces são uma grande ideia — vamos fazer mais desses!
